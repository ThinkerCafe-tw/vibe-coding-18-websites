# EP13 驗收清單

## 逐項檢查

AI 產出後不要只看漂不漂亮，請依序檢查：

- [ ] 首頁第一屏是否說清楚服務適合誰與下一步。
- [ ] 是否收集車籍、年份、里程與服務需求以支撐核心流程，而非只留姓名電話。
- [ ] 是否有工單與報價明細，能區分零件、工資與車主同意狀態。
- [ ] 是否能記錄保養完成項目與下次提醒條件。
- [ ] 是否避免恐嚇式語言推銷維修。
- [ ] 價格、限制、取消或隱私規則是否清楚。
- [ ] 手機版是否能完成主要行動，且文字與按鈕不重疊。

## 主動測試

本講同時有預約名額與報價加總。主動測試：**同一個時段、同一張車牌送出兩次**，本頁第二筆應被攔阻，提示原預約編號，且不新增紀錄、不再次占名額。另開瀏覽器或重新整理後的資料不共用；正式網站須由後端處理跨使用者、跨瀏覽器與同時請求的防重。再用計算機核對報價單各列與總額，留下實際操作結果。


## 資料一致性主動回驗

- [ ] 保養提醒輸入 -5、12.5、abc123，顯示欄位錯誤，不可變成 5、125、123 公里。
- [ ] 0、54300 正常顯示；預約里程留白允許送出，填入小數或負數則擋下。


## 多筆資料與操作一致性回驗

- [ ] 以兩組不同車牌、車主與電話，選仍可預約的時段送出；核對預約編號不同，展開第一筆比對車主、電話、車牌、日期與時段、服務及里程，其他車輛與聯絡欄位也仍對應第一筆。

## 必填文字邊界回驗

- [ ] 逐一把車主姓名、電話、車牌填成三個半形空格（其餘必填合法）再送出，應保留表單並指出錯誤，紀錄與名額不變；全形空格與空字串也要攔阻。
- [ ] 改成正常資料後可送出一次。姓名使用「  測試 王  」時，保存或摘要應為「測試 王」，保留中間空格；其他欄位須符合各自格式。

## 成功後再次編輯回驗

- [ ] 先用合法資料送出並看到確認，再修改姓名或聯絡欄位，上一筆成功提示應立即消失。
- [ ] 逐一測試半形空格、全形空格、空字串、撤回必要同意與重設表單；未通過時不能留下成功提示，既有編號、紀錄內容與名額不得因此改變。
- [ ] 若有日期、時段、班級或模式按鈕，改選也應撤回舊確認。修正資料後可建立新的確認；原本已有編號的本頁紀錄仍可查閱。

## 保養紀錄、提醒與防重回驗

- [ ] ABC-1234 填目前 54,300 公里後預約，紀錄提醒及預約確認均維持 57,000 公里／2026/10/09，不變成 59,300 或預約後六個月。
- [ ] 查 ZZZ-9999 後沒有 52,000、57,000 或舊車日期／進度；改目前里程也不帶回舊提醒。再查 ABC-1234 恢復正確提醒。
- [ ] 用 ZZZ-9999 預約也應顯示無紀錄，不借用 ABC-1234；同車同時段重訂第二筆被擋且名額不變。
