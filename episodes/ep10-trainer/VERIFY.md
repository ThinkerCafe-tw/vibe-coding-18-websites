# EP10 驗收清單

## 逐項檢查

AI 產出後，不要只看第一眼漂不漂亮，請依序檢查：

- [ ] 首頁第一屏是否說清楚服務適合誰與下一步是什麼。
- [ ] 課程包是否有堂數、有效期限、請假、轉讓與退費規則，並有耗課紀錄概念讓學員知道剩餘堂數。
- [ ] 成果案例是否避免保證效果或只展示極端成功者。
- [ ] 補充品建議是否清楚揭露選購性與服務邊界。
- [ ] 手機版是否能完成主要行動，且文字與按鈕不重疊。

## 主動測試

這一講把學員當客人領進門，業態風險等級偏高——最危險的不是版面醜，是**耗課與課程包的數字看起來對、其實算錯**。最招牌的一個觸發：找「已購 10、已上 3、剩 7」這類數字，自己拿計算機核一遍，再逐頁搜同一個堂數看三處一不一致。

**AI 是被告不是法官，畫面才是證據**——它嘴上說「都對了」不算數，回畫面親手核過才算。


## 資料一致性主動回驗

- [ ] 核對明示的 2026/06/29 基準日：續訓包剩 246 天、基礎包剩 21 天，第三包完成；重設耗課後日期與倒數不變。
- [ ] 已過期且仍有堂數的測試課包應顯示已到期且不能扣堂；請假與付款前說明兩處均為「至少於上課前 12 小時告知」。


## 多筆資料與操作一致性回驗

- [ ] 逐張對照目前照片與 alt；主體、動作與場景一致，換圖時同步修正替代文字與下載套件。

## 必填文字邊界回驗

- [ ] 逐一把姓名、電話填成三個半形空格（其餘必填合法）再送出，應保留表單並指出錯誤，紀錄與名額不變；全形空格與空字串也要攔阻。
- [ ] 改成正常資料後可送出一次。姓名使用「  測試 王  」時，保存或摘要應為「測試 王」，保留中間空格；其他欄位須符合各自格式。

## 成功後再次編輯回驗

- [ ] 先用合法資料送出並看到確認，再修改姓名或聯絡欄位，上一筆成功提示應立即消失。
- [ ] 逐一測試半形空格、全形空格、空字串、撤回必要同意與重設表單；未通過時不能留下成功提示，表單仍可修正；本頁不保留逐筆提交歷史。
- [ ] 若有日期、時段、班級或模式按鈕，改選也應撤回舊確認。修正資料後可建立新的確認，取代上一份；不應期待可查閱先前提交。

## 扣堂事件與退費基準回驗

- [ ] 在固定教學基準日、改期次數 0 時，點「當日取消／未出席（扣一堂）」：7→6，提示與規則均使用相同事件名稱；請假改期仍不扣堂。
- [ ] 按實付金額與未上比例核可退本金；行政費不可使退款超過本金。
- [ ] 兩次諮詢僅顯示新摘要；三分頁不承諾逐筆歷史。
