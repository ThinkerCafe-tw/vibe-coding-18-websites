# EP03 對話提示卡

以下為第 3 講第 5.1 節既有提示詞。請先核對需求與資料，再用自己的話與 AI 確認；示意資料不要當成真實商家資料。

## 教材提示詞

```text
你是網頁設計老師與前端工程師。
請幫我做成一個攝影師作品集網站，並讓它適合上傳到 GitHub 和 Vercel 部署。

【攝影師資料】
名稱：小柯攝影工作室
地區：台中
服務類型：婚紗、婚禮紀錄、形象照
品牌主張：自然、不過度修飾，重視情緒與現場關係
主要客群：準新人、小型品牌主、需要形象照的專業工作者

【網站目標】
1. 讓第一次來的客人快速看懂攝影風格
2. 讓作品依照類型清楚分類
3. 說明拍攝流程、方案內容、交件時間與加選規則
4. 引導客人填寫詢問表單
5. 讓網站可部署為單頁靜態網站（靜態網站＝內容固定、伺服器原樣送出的網頁，不需後端程式即時運算，最省事也最好部署）

【必要區塊】
1. 首頁主視覺：攝影師名稱、服務類型、一句話主張、兩個按鈕「看作品」「詢問檔期」
2. 作品分類：婚紗、婚禮紀錄、形象照，每類 4 到 8 張示意圖（placeholder）
3. 案例說明：每一類用 2 到 3 句說明拍攝情境
4. 服務方案：方案名稱、內容、價格區間、交件時間、加選規則
5. 拍攝流程：詢問、溝通、拍攝、精修、交件
6. 關於我：攝影師介紹與工作方式
7. 詢問表單：姓名、聯絡方式、拍攝類型、日期、地點、預算、留言
8. 頁尾：Email、Instagram、服務地區、版權聲明

【視覺風格】
照片優先、留白、專業、安靜、不要過度裝飾。
背景可以用白色、深灰或低飽和米色。
按鈕要清楚，但不要太花。

【技術要求】
1. 請做成一個可以直接打開的單一 index.html 檔案。
2. CSS 寫在同一個檔案內。
3. 使用語意化 HTML，例如 header、main、section、footer。
4. 圖片先用免費圖庫（如 Unsplash）的示意圖，並用註解標出日後要替換的圖片檔名。
5. 每張圖片都要有 alt 文字。
6. 使用響應式設計，桌機作品集可三欄，手機改為單欄。
7. 文字在手機上至少要容易閱讀，按鈕要容易點。
8. 表單不需要真的送出到後端，但要有清楚欄位與送出按鈕。
9. 不要編造得獎紀錄、客戶評價或合作品牌。
10. 請在 HTML title 與 meta description 放入適合 SEO 的文字。
```

## 原有對話流程

# EP03 對話卡

這張卡的重點不是背指令，而是把「畫面完成」一路推進到「公開網址可重做驗收」。

## 1. 先交代目標與素材

> 我想做一個攝影師作品集。請先核對我提供的服務、方案、圖片和授權，不要補寫獎項、評價、品牌或客戶姓名。先整理成可批准的規格，不要施工。

## 2. 批准後完成本機作品

> 規格已確認，可以開始。請做手機優先的網站，第一屏要說清楚服務與自然、不過度修飾的風格，接著呈現作品、方案、關於與詢問入口。

## 3. 要求可重做的驗收

> 請分別檢查桌機、一般手機與最窄手機；實際測試表單必填、13 張圖片路徑與 SEO。不要只告訴我程式看起來正確。

## 4. 保存與發布

> 本機驗收通過後，建立內容清楚的版本並推到公開 repo 的 main。等待已連結的 Vercel 完成部署，再開啟固定 production URL 驗收。

## 5. 最後只看四個停點

> 請用白話回報：作品已整理、手機已檢查、版本已保存、公開網址可驗收；每個停點都要有實際證據支持。
