教學虛構示例 · 單頁網站專案總複習

不是先問「網站多少錢」，而是先把邊界說清楚。

從網站類型、需求訪談、功能層級，到報價、交付、驗收與維護， 把一個網站專案真正需要確認的六個模組放在同一張地圖上。

開始整理專案 直接看驗收表
先分類 先判斷是形象、作品部署、預約、會員，還是交易平台。
再畫邊界 包含、不包含、新增另計，必須在製作之前說清楚。
最後才驗收 手機、表單、資料、付款與 SEO 分開檢查，不用一句「做好了」帶過。
01 · WebsiteType

五張等級卡：先看你正在做哪一種網站

網站類型會直接影響資料、帳號、後端與驗收方式。 功能越接近「預約、會員、付款與多人協作」，責任邊界就越需要被明確定義。

1

功能等級 · 基礎

形象

適合需要說清楚品牌、服務、聯絡方式與核心行動的店家或個人。

主要風險：資訊過時、聯絡方式失效、手機閱讀不佳。
2

功能等級 · 展示＋發布

作品與部署

適合作品集、活動頁、專案展示，需處理版本、網域與部署網址。

主要風險：圖片過重、部署權限不清、正式版與舊版混淆。
3

功能等級 · 流程

預約與排程

適合診所、教練、工作室、住宿等，需要選日期、時段與人員的服務。

主要風險：重複預約、狀態不一致、前端顯示不等於後端鎖位。
4

功能等級 · 身分＋資料

會員與課程

適合登入、課程紀錄、堂數、會員資料與個人化內容。

主要風險：權限、個資保存、堂數與交易紀錄無法追溯。
5

功能等級 · 交易＋平台

交易與平台

涉及付款、訂單、退款、平台角色或第三方服務整合。

主要風險：金流通知、訂單一致性、退款與權限責任界線。

03 · ScopeItem + QuoteLine

報價不是一個總價，要拆成可以驗收的工作

報價拆分為工作項目、估時、價格與備註。 真正報價應依頁面數、功能數、整合範圍、時程與維護責任重新估算。

工作項目 範圍 估時 價格 驗收方式
單頁資訊架構與 RWD 包含 6 小時 — 手機、平板、桌機閱讀測試
靜態表單互動 包含 3 小時 — 欄位狀態與成功提示可操作
正式會員資料庫 不包含 — — 此版本沒有建立正式會員後端
第三方金流串接 新增另計 另估 另估 需包含付款通知與訂單狀態驗證
上線後內容維護 新增另計 按次或週期 另議 依更新紀錄逐項確認

報價四個拆分軸

頁面數 首頁、服務、作品、會員頁等，是否屬於不同頁面。
功能數 搜尋、表單、預約、登入、付款，各自是不同功能責任。
整合項目 網域、分析、地圖、行事曆、資料庫、金流等第三方服務。
維護 誰更新、多久更新、異常怎麼回報，與製作本身分開。
ScopeItem 物件示例 { 項目、是否包含、驗收方式 }
QuoteLine 物件示例 { 工作項目、估時、價格、備註 }
04 · DeliveryAsset

網站交付，不只有一個網址

專案結束前，把原始檔、網址、帳號權限與文件逐一交回，避免未來只有製作者本人知道網站怎麼運作。

01

原始檔

HTML、CSS、JS、合法可交付素材與最終版本檔案。

02

部署網址

正式網址、部署平台位置，以及哪一個版本目前對外公開。

03

帳號權限

帳號歸屬、管理權限、交接方式。密碼不直接寫進公開文件。

04

文件

更新方式、部署流程、功能限制、第三方服務與維護規則。

DeliveryAsset 物件示例 { 檔案、帳號、網址、文件 }

06 · MaintenanceRule

交付不是結束，還要先講清楚誰負責維護

網站最容易出問題的時候，往往不是製作當天，而是幾個月後內容改了、帳號換人、服務失效，卻沒有人知道誰處理。

更新頻率

定義內容是每週、每月、活動前更新，還是僅在收到需求時修改。

責任人

指定誰提供正確資料、誰更新網站、誰能操作正式帳號。

費用

分清原專案保固、內容更新、功能新增與第三方服務費，不混成一筆。

回復流程

異常先記錄網址、時間、操作步驟與畫面，再判斷是內容、前端、後端或第三方服務。

兩條不能混在一起的責任線

個資保存：這個教學原型可用 localStorage 保存測試資料，但正式會員、預約、訂單與敏感個資不應只存在使用者瀏覽器，必須依正式系統需求設計後端、權限與保存規則。

付款成功：使用者看到「成功頁」不等於商家已確認收款。正式交易應由後端驗證金流服務的付款通知與交易狀態，再決定訂單是否成立。

MaintenanceRule 物件示例 { 更新頻率、責任人、費用 }

總複習

一個能交付的網站，要同時回答六個問題。

這是哪一類網站？需求從哪裡來？哪些工作包含在報價裡？ 最後交付什麼？怎麼驗收？上線後誰負責？ 六件事都能回答，專案才真正有邊界。
