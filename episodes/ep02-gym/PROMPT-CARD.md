# EP02 對話提示卡

以下為第 2 講第 5.1 節既有提示詞。請先核對需求與資料，再用自己的話與 AI 確認；示意資料不要當成真實商家資料。

## 教材提示詞

```text
你是網頁設計老師與前端工程師。
請幫我建成一個「健身房網站」的單頁網站原型，做成一個可以直接打開的單一 index.html。

【網站目標】
單頁健身房網站，強調視覺風格、教練信任、課程方案、首次體驗流程與透明退費。

【使用者情境】
使用者第一次進入網站時，需要在手機上快速判斷這個服務是否適合自己，並能完成主要行動：預約首次體驗、查看課程方案、理解退費規則。

【必要區塊】
1. Hero 首頁：場館名稱、定位、主張、首次體驗按鈕
2. 教練團隊：姓名、證照、專長、適合族群
3. 課程方案：團課、私教、月費、年費、入會費
4. 體驗流程：預約、抵達、器材介紹、不強迫推銷承諾
5. 空間設備：器材、尖峰提醒、更衣室、女性友善區
6. 退費與合約：月繳、年繳、終止規則、客服窗口

【資料欄位】
請在頁面中示範下列資料結構：
1. GymProfile：場館名稱、地區、定位、營業時間
2. Coach：姓名、證照、專長、適合對象
3. TrainingPlan：方案名稱、價格、期間、限制、退費規則
4. TrialBooking：姓名、聯絡方式、時段、目標、是否首次
5. FacilityFeature：設備名稱、說明、是否提供
6. TrustEvidence：學員見證、照片來源、評論摘要

【設計要求】
1. 請使用清楚的 HTML結構與 CSS，建成一個可以直接打開的單一 index.html，CSS 寫在同一個檔案裡。
2. 請使用 RWD（響應式網頁設計），用 CSS media query 讓手機、平板、桌機都可讀、可點。
3. 請避免假評價、假資歷、假價格或過度承諾。
4. 表單與按鈕要有清楚的互動狀態，可以用靜態示意，不需要真的送出到伺服器。
5. 全文用繁體中文；價格、教練資歷、學員見證等以示意內容佔位，並用 HTML 註解標出日後須替換為真實資料的欄位。
```


## 必填文字驗證

- 姓名、聯絡方式、想改善的目標等必填文字送出前去除首尾空白；空字串或只有空白時保留表單並提示，不建立紀錄、不占名額。內容中間的正常空格應保留。共用驗證程式隨本講 ZIP 提供，直接開檔也要生效。

- 沿用本公開套件時，請保留 ZIP 內的共用驗證程式與相對路徑，解壓後可直接開啟 index.html。

## 表單確認與新草稿

- 成功送出後，只要修改輸入、切換選項、重設表單或再次送出未通過驗證，立即撤回上一筆成功提示。
- 只撤回表單確認，不刪除原本已有編號的本頁紀錄，也不重複扣除名額；使用者可從本頁紀錄查閱先前資料。
- 程式內部在成功後清空表單時，先完成清空再顯示這一次確認；使用者開始填寫下一筆時才撤回。
