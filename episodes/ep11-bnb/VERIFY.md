# EP11 驗收清單

## 逐項檢查

第一版畫面出來後，接著問 AI：

```text
請根據剛才的民宿訂房網站，幫我整理資料模型。

請用表格列出：
1. RoomType 房型
2. Room 實際房間
3. Availability 每房每日房況
4. Order 訂單
5. Payment 付款
6. Guest 旅客

每個資料物件請列出欄位、欄位說明、範例值。
請特別說明 RoomType 和 Room 的差別，以及 Availability 為什麼要用「每房每日一筆」來設計。
```

這一步讓學生理解：卡片、表單、日曆都對應到資料，沒拆清楚就難維護。

## 主動測試

接著補上狀態流程：

```text
請幫我補上民宿訂房的狀態流程。

請包含：
1. 房況狀態：可訂、保留中、已預訂、入住中、清潔中、封鎖/維修（房東手動不開放）
2. 訂單狀態：待付款、已確認、已取消、已退款、已完成
3. 付款狀態：未付款、付款中、付款成功、付款失敗、已退款

請用白話說明每一個狀態如何轉換。
也請說明為什麼付款成功頁不能取代 webhook。
```


## 多筆資料與操作一致性回驗

- [ ] 同日期先付清 201 房，再送第二筆 202 房。編號須不同；取消第二筆後切回第一筆，其已確認、收款、交易號、房況與事件皆不變。
- [ ] 分別走未付款取消、保留逾時、付款失敗後取消、付款中取消，不得顯示完成退款；即使直接觸發退款事件也不得改變狀態或產生紀錄。
- [ ] 距入住日未滿 3 天付清再取消，維持已取消／付款成功，不能退款；距入住日 3–13 天付清再取消可退 50%，完成退款後不能重複退。
- [ ] 快速按付款成功、取消、送新單，等舊回呼返回，新單仍待付款；查看先前訂單不會停止另一筆的保留倒數。
- [ ] 逐張對照目前照片與 alt；主體、動作與場景一致，換圖時同步修正替代文字與下載套件。
