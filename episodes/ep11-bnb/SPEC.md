# EP11 施工規格

本規格整理自《網頁設計》第 11 講第 4 節資料模型與狀態流程、第 5 節實作與驗收，以及第 6 節正式營運延伸，並對照本練習站的實際功能；是學員審閱與實作依據。

## 網站目標

製作「山邊晨光民宿」的手機優先訂房原型。旅客能看房型、查日期與人數、核對總價和取消政策、填資料，再走完付款成功、付款失敗重試、保留逾時與取消退款流程。

品牌設定為宜蘭礁溪的小型手作民宿，採米白、木褐、深苔綠，呈現溫暖安靜的生活感。每一步都要讓人看懂房況、訂單與付款的差別。

## 使用者情境

1. 週末短住的夫妻：比較檜木雙人房與日期，確認週末價、交通及取消規則後送出訂房。
2. 小家庭：查看晨光四人房的人數上限、加人費、早餐與設備限制，核對完整住宿費用。
3. 付款中的旅客：看見房間暫時保留與剩餘時間；付款失敗可重試，逾時或取消則釋放房間。
4. 學員與房東：從逐房逐日房務板觀察「同一間房同一晚只能賣一次」，並區分前端模擬與正式後台的工作。

## 必要區塊

1. 首頁主視覺：民宿名稱、生活主張、環境照片、「查看房型」與「查詢日期」入口，以及今晚可訂房數。
2. 空間故事：主人、早餐、在地生活與經營理念。
3. 房型列表與詳情：檜木雙人房、晨光四人房；各列照片、人數、床型、設備、樓層與限制、平日價、週末價及加人規則。
4. 日期查詢與房務板：今天起 14 天、實際房間 201／202／301 的每日狀態；入住日、退房日、人數、房型選擇。
5. 訂房摘要：逐晚房價、週末晚數、連住折扣、加人費、每筆清潔費、總額，以及目前適用的退款階梯。
6. 訂房表單：姓名、Email、電話為必填，另有備註；日期與房況通過後才建立待付款訂單。
7. 付款模擬與訂單卡：訂單編號、房間、日期、旅客、金額、三種狀態、保留倒數與操作紀錄；提供成功、失敗、逾時、取消、完成退款及重設操作。
8. 在地指南：三個推薦地點及適合的遊逛情境。
9. 交通指引：開車、搭車、停車及夜間抵達資訊。
10. 常見問答與聯絡：入住、退房、早餐、寵物、取消及改期；電話文字與連結一致。

## 資料欄位

下表是依書稿整理的資料模型。現有成品用 JavaScript 物件與當前頁面狀態模擬；正式營運時才持久保存至資料庫。

| 資料物件 | 必要欄位 | 本練習對應 |
|---|---|---|
| RoomType 房型 | 房型 ID、名稱、基本／最多人數、床型、坪數、設備、限制、照片、平日價、週末價 | 檜木雙人房基本 2 人、最多 3 人；晨光四人房基本 4 人、最多 6 人 |
| Room 實際房間 | 房號、房型 ID、是否上架 | 201／202 屬雙人房；301 屬四人房 |
| Availability 每房每日房況 | 房號、日期、狀態、不可售原因、當日價格、保留到期時間 | 房號＋日期識別一筆；原型價格由房型與日期推算，保留期限與關聯訂單編號對應各筆訂單 |
| Order 訂單 | 訂單編號、房型、房號、入住／退房日、入住晚數、人數、旅客資料、備註、總額、狀態、保留期限、取消時退款比例、應退金額 | 訂單卡與操作紀錄；保留 15 分鐘 |
| Payment 付款 | 訂單編號、金流商、交易號、金額、付款狀態、通知時間 | 原型顯示模擬交易號與付款狀態；正式版保存金流通知與驗證結果 |
| Guest 旅客 | 姓名、Email、電話、入住次數 | 第一版旅客資料嵌於各筆訂單，入住次數屬延伸欄位 |

RoomType 是分類，Room 是實體。一個房型可有多間房，賣出 201 不代表 202 也售罄。Availability 必須每房每日一筆；多晚住宿要找到同一間房在所有入住夜晚都可訂，退房日不占用一晚。

## 日期、計價與取消規則

1. 日期不可在過去，退房日至少晚於入住日一天。成品可訂範圍為今天起 14 天，退房可選第 15 天；範圍外不建立訂單。房況為保留、已預訂、入住、清潔或封鎖時，不能再次出售。
2. 週五、週六採週末價。檜木雙人房平日 NT$3,200、週末 NT$3,800；晨光四人房平日 NT$4,800、週末 NT$5,600。
3. 超過基本人數，每人每晚加 NT$800；每筆清潔費 NT$300。住滿 3 晚，只有房費打 9 折。總額＝逐晚房費－房費折扣＋加人費＋清潔費。
4. 退款依取消當日距入住日的日數計算，區間互斥，退款金額為已付款總額乘比例並四捨五入至整元。

| 距入住日 | 程式邊界 | 退款比例 |
|---|---|---|
| 30 天以上 | 日數 ≥30 | 100% |
| 14–29 天 | 14 ≤ 日數 <30 | 75% |
| 3–13 天 | 3 ≤ 日數 <14 | 50% |
| 未滿 3 天 | 日數 <3 | 0% |

距入住日 3 天以上可來電申請改期，每筆訂單限一次；未滿 3 天不接受改期。改期是來電申請規則，本原型沒有線上改期按鈕。摘要、FAQ、頁尾與訂單說明使用同一規則。

## 狀態與必要互動

| 對象 | 狀態與轉換 | 應看見的結果 |
|---|---|---|
| 房況 | 可訂 → 保留中 → 已預訂 → 入住中 → 清潔中 → 可訂；封鎖／維修由房東另行開放 | 送出後占住房間；付款成功才成為已預訂；逾時或取消釋放 |
| 訂單 | 待付款 → 已確認／已取消；已確認 → 已完成／已取消；已取消且已收款、符合退款資格 → 已退款 | 已完成、已退款為終態；取消與退款完成分成兩步 |
| 付款 | 未付款 → 付款中 → 付款成功／付款失敗；付款失敗可重試；付款成功且符合退款資格，退款完成 → 已退款 | 失敗不等於訂單結束，保留期限內仍可重試 |

- 本頁可操作：查房、建立訂單、15 分鐘保留倒數、模擬付款成功／失敗、模擬逾時、取消、完成退款與重設。
- 已付款取消依已收金額與取消階梯計算應退金額。未付款取消或逾時維持「已取消／未付款」，沒有退款入口或退款事件；已付款但退款比例 0% 也不能完成退款。只有已收款且應退金額大於 0 才提供「完成退款」，完成後才進退款終態。
- 入住、清潔、封鎖狀態以預設房況展示；已完成與房東開關房況屬完整模型，現有前台未提供對應後台操作。

## 設計要求與第一版範圍

1. 成品為可直接開啟的單一入口 index.html，CSS 與本講互動同檔，共用驗證與圖片使用隨包提供的檔案；手機、桌機皆可閱讀操作。
2. 手機日期、表單與按鈕不重疊，主要按鈕至少 44px；整頁無橫向溢出。修改手機時保留桌機版面。
3. 付款明確標為模擬，不收信用卡資料；使用虛構練習資料，沒有假評論、假證照或假媒體報導。
4. 原型資料保存在當前頁面，重設／重載回到示範資料；前端保留不能當作跨瀏覽器的併發鎖房。
5. 正式版延伸：後端以交易同時建立訂單與逐房逐日保留，驗證 webhook 後確認付款，保留到期自動釋位；房東後台管理房況、訂單、價格與封鎖日期。付款返回頁只提示結果，不能取代 webhook 主信源。

## 驗收重點

- [ ] 房型資訊完整；雙人房兩間與四人房一間的數量、日期狀態能分開核對。
- [ ] 過去日期、退房早於入住、滿房與超出開放範圍的訂房被阻擋；連住必須同一房間全程可訂。
- [ ] 用平日／週末、3 晚折扣、加人與清潔費逐項重算，總額相符。
- [ ] 送出後顯示待付款／保留中／未付款；付款失敗仍保留且可重試，付款成功顯示已確認／已預訂／付款成功。
- [ ] 付款逾時與取消會釋放房間；同一間房同一晚重複訂房被阻擋，另一間可用房仍可出售。
- [ ] 已付款取消與完成退款分開顯示；核對退款比例及金額，退款完成後操作停在終態。
- [ ] 分別測距入住日 2、3、13、14、29、30 天，退款比例依序為 0%、50%、50%、75%、75%、100%；摘要亮起階梯、FAQ、頁尾、訂單文字一致。14 天以上以政策函式與摘要驗算，不視為 14 天房況窗內可訂。
- [ ] 改期條款在所有位置一致：距入住日 3 天以上來電申請一次，未滿 3 天不接受。
- [ ] 375 與 1280 寬度無破圖、橫向捲動或 console 錯誤；電話與導覽可到正確目標。
- [ ] 教學頁、SPEC.md 與 ZIP 規格一致；能說明正式版資料庫、後端鎖房、webhook 與後台各自負責什麼。

## 本練習包的素材

照片分別用於民宿環境、檜木雙人房與晨光四人房。練習重點是房型、人數、日期、房價與付款保留流程；換圖時讓照片與所屬房型一致，並保留手機上的房型資訊。來源說明見 `ATTRIBUTION.md`。


## 本頁資料與操作一致性

- 每筆新訂單使用唯一編號，訂單、付款、交易號、已收金額、房號與逐日房況按編號關聯保存。本頁訂單清單可切回先前訂單，查看原摘要、付款與操作紀錄；取消另一筆不影響原已確認訂單。
- 付款回呼與保留計時器綁定原訂單及付款嘗試，切換查看、取消、新增或全部重來後，舊回呼不可更新其他訂單。
- 未付款取消／逾時維持已取消／未付款，不顯示完成退款，也不建立退款事件。已收款且應退金額大於 0 才能退款；0% 取消保留原付款成功紀錄。
- 本頁示例只存於目前頁面。重新整理或按「全部重來」會一併清空全部訂單、付款與房況並回到初始示例；頁內重設後編號序號繼續遞增。
- 圖片替代文字依目前照片可見內容描述，避免沿用舊構圖、人物身分或無法由照片確認的地名。
- `images/hero.jpg`：稻田與山巒前的三層民宿。
- `images/room-double.jpg`：木地板雙人房，床旁有木框窗與椅子。
- `images/room-quad.jpg`：設有兩張雙人床的客房，窗外可見山景。

## 必填文字驗證

- 姓名、Email、電話等必填文字送出前去除首尾空白；空字串或只有空白時保留表單並提示，不建立紀錄、不占名額。內容中間的正常空格應保留。共用驗證程式隨本講 ZIP 提供，直接開檔也要生效。

## 房型人數限制

- 報價與送出共用房型人數驗證：入住人數必須為正整數且不超過房型上限；檜木雙人房最多 3 人，四人房最多 6 人。無效時不建立訂單、不保留房間、不開放付款；換房型後重新核對。
