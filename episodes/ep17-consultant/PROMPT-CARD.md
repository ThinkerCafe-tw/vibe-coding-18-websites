# EP17 對話提示卡

以下為第 17 講第 5.1 節既有提示詞。請先核對需求與資料，再用自己的話與 AI 確認；示意資料不要當成真實商家資料。

## 教材提示詞

```text
你是網頁設計老師與前端工程師。
請幫我製作一個「顧問預約與付款網站」單頁原型。

【網站目標】
讓客戶能理解顧問方案、預約時段、付款流程、付款成功/失敗頁與交付邊界。

【必要區塊】
1. 首頁：顧問定位、適合客戶、預約諮詢按鈕
2. 服務方案：方案名稱、價格、時長、交付物、不包含項目
3. 案例與文章：案例摘要、方法論文章、可驗證成果
4. 預約表單：公司類型、問題描述、預算、可預約時段
5. 訂單摘要：方案、金額、稅額、總額、預約時間、退款規則
6. 付款流程示意：前往付款、付款中、付款成功、付款失敗、使用者取消
7. 交付說明：會議連結、會前資料、交付物、後續追蹤

【資料模型】
請示範以下六張表，並用外鍵 id 串接（對應第 4 節表 17-2）：
- ConsultingPackage(id, 名稱, 價格, 時長, 交付物, 不包含項目)
- ConsultationBooking(id, 客戶, 方案 id, 預約時間, 需求摘要, 狀態)
- Order(id, 預約 id, 金額, 稅額, 總額, 狀態)
- PaymentTransaction(id, 訂單 id, 金流商, 交易編號, 付款狀態, 回傳時間)
- PaymentCallback(交易編號, 原始回傳資料, 驗證結果, 處理時間)
- DeliveryRecord(預約 id, 會議連結, 交付物, 完成狀態, 後續事項)

【互動示意】
用少量 JavaScript示範：選擇不同方案會改變訂單金額；點擊付款按鈕後進入付款中狀態；可切換顯示付款成功、付款失敗、使用者取消三種結果；成功後顯示下一步交付說明。

【技術補充】
請在頁面中補一張「原型 / sandbox / 正式環境」差異表。內容要包含：是否使用真實商家帳號、是否需要後端、是否驗證 webhook 簽章、是否可以收真實信用卡、是否處理發票與退款。

【設計要求】
請做成一個可以直接打開的單一 index.html 檔案（HTML、CSS 寫在同一個檔案內），使用 RWD。畫面要清楚標示這是金流流程原型，尚未真正串接藍新或綠界。不要把商店代號、API 金鑰或交易簽章寫在前端。不要承諾保證成效、保證營收倍增或不可能驗證的結果。
```
